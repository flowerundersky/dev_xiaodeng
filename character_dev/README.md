隐患：
1、锁逻辑无错误，但系统调用返回码不符合用户态应用的普遍预期。当等待锁被信号打断时返回 `-ERESTARTSYS`，虽然内核会做转换，但不符合通用驱动实践，存在应用程序异常的潜在风险；应用如果对返回码处理不完备，会出现报错、逻辑异常。不是崩溃 bug，是可移植性、兼容性隐患。通常返回内核转换给用户态的 `-EINTR`
2、怎么判断打开的进程全部关闭，当在多个进程同时打开的情况下，未全部关闭就卸载内核模块，产生oops问题
解决：记录open的数量，exit里设备的卸载的执行需要条件，确保所有的open全部关闭，不能再打开新的open。
